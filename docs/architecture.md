# 系统架构与模块设计规约 (System Architecture Specification)

## 1. 总体分层架构 (Layered Architecture)

本系统采用经典前后端分离（B/S）分层架构：
- **展现层 (Presentation Layer)**：Vue 3.4 + TypeScript 5.3 + Vite 5.1 + Element Plus 2.6；
- **控制层 (Controller Layer)**：Spring Boot 3.2 Web RESTful Controllers，负责请求分发、入参 `@Valid` 校验与统一响应包装；
- **安全认证层 (Security & Auth Layer)**：Spring Security 6 + JJWT，无状态 Token 拦截与全端注销版本控制；
- **服务层 (Service Layer)**：核心业务逻辑编排、状态机控制与事务边界（`@Transactional`）；
- **持久层 (Persistence Layer)**：MyBatis-Plus 3.5 + MySQL 8.0，逻辑删除与审计字段自动填充；
- **基础设施与系统运维**：物理磁盘多格式文件存储、定时备份引擎流水记录。

## 2. 核心规格指标 (Core Metrics)

- **需求基线**：195 项全量冻结需求（138 项核心业务 + 43 项公共功能 + 14 项非功能约束；`ISSUE-001` 待确认）；
- **数据模型**：42 张物理数据表（39 张核心业务表 + 3 张系统支撑表；阶段5累计就绪 18 张表）；
- **接口端点**：125 个独立单方法单路径 RESTful API 端点（`API-001` 至 `API-125`）；
- **前端体系**：36 条菜单路由，21 个独立 Vue 页面组件，15 条复用路由，11 个通用公共组件。

## 3. 阶段5 核心业务架构与规则正式冻结基线 (Phase 5 Frozen Specifications)

### 3.1 安全准入测试规则正式冻结 (SAFE-004)
- **抽题与组卷机制**：系统抽取当前任务专属题库（`task_id` 匹配）与全校通用题库（`task_id IS NULL`）中所有状态为启用（`status=1, is_deleted=0`）的客观试题，在服务端/客户端执行真实随机乱序洗牌（`Collections.shuffle(list)`）。
- **范围与边界冻结**：由于当前阶段数据模型（`internship_task` 及试题表）未配置按单选/判断等题型划分的题量抽选比例字段，**当前系统正式确定并冻结为“全库启用试题全量抽取 + 随机乱序”，暂不支持按题量和题型比例抽题**。
- **前置准入强校验**：未完成全部必学安全规程资料阅读前，强行阻断试卷抽取与交卷操作（返回 `400 Bad Request`）。
- **交卷逐题核验**：试卷题目非空校验，逐题校验试题有效启用状态及所属任务归属，严禁跨任务试题作答。

### 3.2 教师分配与圈定学生管理边界 (TASK-003, ASSIGN-001 ~ ASSIGN-003)
- **严格名单校验**：批量或单个指派指导教师时，严格校验每个学生必须存在于当前任务圈定名单中；**遇到不在名单中的学生 ID 立即抛出 400 阻断并回滚事务，严禁静默跳过**。
- **数据权限隔离**：任务圈定学生列表及导师列表仅限 `DEPT_ADMIN` 与 `SYS_ADMIN` 查询，学生与教师访问直接返回 `403 Forbidden`；院系负责人跨院系查询直接 403 拦截。
- **禁止隐式默认院系**：创建任务时严禁使用 `deptId=1L` 等默认兜底，管理员与院系负责人必须显式指定或绑定院系。

### 3.3 实习申报与 APPLY-009 审核强锁定规则
- **组织模式自主确认**：前端实习组织模式禁止预设 `DISTRIBUTED` 等隐式默认值，强制学生在填报时自主选定并校验。
- **APPLY-009 一票否决**：申请处于 `APPROVED` 状态时，后端 Service 层统一拦截普通新增、编辑、覆盖或删除操作；前端表单切换为物理只读模式；重大信息变更必须进入变更审批流程。
